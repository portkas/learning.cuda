# 统一内存

统一内存（Unified Memory）是一种内存管理技术，旨在简化多处理器（如 CPU 和 GPU）之间的内存访问和数据共享。它通过提供一个单一的、全局的内存地址空间，允许 CPU 和 GPU 无缝地访问相同的数据，而无需显式地在两者之间手动复制或同步数据。

## 1.概念

1. 单一内存地址空间：统一内存将 CPU 和 GPU 的内存合并为一个逻辑上的全局地址空间。这意味着无论数据存储在 CPU 内存还是 GPU 内存中，都可以通过同一个指针访问。
2. 自动数据迁移：当 CPU 或 GPU 访问数据时，系统会自动将数据迁移到访问者的本地内存中。例如，如果 GPU 需要访问某个数据，而该数据当前存储在 CPU 内存中，系统会自动将数据迁移到 GPU 内存中，并更新指针。

## 2.工作机制

1. 页面迁移引擎(PME)：当发生页面错误（即访问的数据不在本地内存中）时，PME 会自动将数据从远程内存迁移到本地内存。
2. 自动内存管理：应用程序无需关心数据的具体存储位置。开发者只需通过简单的 API（如 `cudaMallocManaged()`）分配内存，系统会自动管理数据的迁移和同步。

## 3.使用方法

1. 内存分配：通过调用 `cudaMallocManaged()` 分配统一内存，函数会分配一块统一内存，并返回一个指针，该指针可以被 CPU 和 GPU 共同访问。
2. 数据访问：CPU 和 GPU 可以直接通过指针访问分配的内存，无需手动管理数据的传输；

```cpp
// CPU 代码
int* data;
cudaMallocManaged(&data, size);
data[0] = 42;  // CPU 写入数据

// GPU 代码
__global__ void kernel(int* data) {
    data[0] = 43;  // GPU 修改数据
}
kernel<<<1,1>>>(data);
```

## 4. Pre-Pascal GPU

在具有 Pre-Pascal GPU（如 Tesla K80，基于 Kepler 架构）的系统上，统一内存（Unified Memory）的行为与 Pascal 及更高版本的 GPU 架构有所不同。这是因为 Pre-Pascal GPU 架构不支持硬件级别的页面迁移引擎（PME），因此统一内存的管理完全依赖于软件实现。

### 4.1 内存分配

在 Pre-Pascal GPU 上，调用 `cudaMallocManaged()` 分配的托管内存（managed memory）会根据当前活动的 GPU 设备进行初始分配。

1. 托管内存最初会被分配在调用时处于活动状态的 GPU 设备内存中。
2. 驱动程序会为这些分配的页面设置页表条目，以便系统知道这些页面最初驻留在该 GPU 上。

### 4.2 CPU访问托管内存

当 CPU 首次访问托管内存时，会发生页面错误（page fault），因为这些页面最初驻留在 GPU 内存中。CPU 的页面错误处理程序会触发以下操作：

1. 页面迁移：GPU 驱动程序会将页面从 GPU 内存迁移到 CPU 内存。
2. 更新页表：更新页表条目，以便后续访问可以直接在 CPU 内存中完成。GPU 驱动程序会将页面从 GPU 内存迁移到 CPU 内

### 4.3 GPU访问托管内存

在 Pre-Pascal GPU 上，CUDA 运行时必须确保所有托管内存页面在内核启动前都迁移到目标 GPU 的设备内存中。

1. 没有硬件页面迁移支持：Pre-Pascal GPU 不支持页面错误和动态页面迁移。
2. 数据必须驻留再GPU上：为了保证内核能够访问数据，所有相关页面必须在内核启动前显式迁移到 GPU 内存。

在启动内核之前，CUDA运行时会执行以下操作：

1. 检查页面位置：运行时会检查托管内存页面的当前位置。
2. 显式迁移页面：如果页面不在目标 GPU 内存中，运行时会将它们迁移到目标 GPU 内存。
3. 启动内核：只有当所有页面都迁移到目标 GPU 内存后，内核才会启动。

## 5. Pascal GPU

在 Pascal GPU 上，统一内存的页面迁移是动态的，且迁移开销包含在内核运行时间中。这种行为虽然简化了编程模型，但在某些情况下可能会导致内核运行时间增加。通过预取页面和优化内存访问模式，可以有效减少页面迁移的开销。

### 5.1 托管内存延迟分配

在 Pascal GPU 上，调用 `cudaMallocManaged()` 时，托管内存可能不会立即进行物理分配，而是采用“首次访问”策略。这意味着物理内存的分配和页表条目的创建会在首次访问时完成。

* 如果 CPU 首次访问托管内存，页面会被分配到 CPU 内存。
* 如果 GPU 首次访问托管内存，页面会被分配到 GPU 内存。

### 5.2 硬件页面错误支持

Pascal GPU 引入了硬件页面错误处理和页面迁移引擎（PME），这使得 GPU 在访问非驻留页面时能够自动触发页面迁移。因此：

* 内核启动时，CUDA 运行时不会自动将所有页面从 CPU 内存迁移到 GPU 内存。
* 当 GPU 内核访问某个页面时，如果该页面不在 GPU 内存中，页面迁移引擎会自动将页面从 CPU 内存迁移到 GPU 内存

### 5.3 如何建少页面迁移开销

1. 预取页面：通过 `cudaMemPrefetchAsync()` 将数据显式迁移到 GPU 内存，避免运行时的动态迁移；
2. 内存访问局部性优化：使用 `cudaMemAdvise()` 提示驱动程序关于数据的访问模式，帮助优化页面迁移；
